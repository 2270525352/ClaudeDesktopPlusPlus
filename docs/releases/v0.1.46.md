# v0.1.46 发布说明

本版本修复 `v0.1.45` 的两个 macOS 安装包下载后被系统提示“应用已损坏”的问题。

## 问题原因

`v0.1.45` 的 ARM64 与 Intel x64 应用虽然编译和 DMG 打包成功，但应用包中没有 `_CodeSignature`。从浏览器下载后，macOS Gatekeeper 会拦截完全未签名的应用。

## 修复内容

- macOS ARM64 和 Intel x64 构建默认使用 Tauri ad-hoc 代码签名。
- GitHub Actions 在发布前执行 `codesign --verify --deep --strict`。
- CI 会挂载生成的 DMG，再次验证 DMG 内部应用的签名，防止封装过程破坏签名。
- 任一架构缺少签名、签名失效或 DMG 内找不到应用，Release 都不会发布。

## macOS 首次启动

ad-hoc 签名用于开源项目在没有 Apple Developer ID 证书时保证应用完整性，解决完全未签名导致的“应用已损坏”。macOS 仍可能提示开发者未验证，此时请在“系统设置 > 隐私与安全性”中确认打开。

要实现下载后完全无系统确认，需要使用付费 Apple Developer ID 证书签名并提交 Apple 公证。
