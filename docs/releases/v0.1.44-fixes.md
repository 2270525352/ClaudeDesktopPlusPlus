# v0.1.44 修复说明

本版本集中修复两个会直接影响 Claude Desktop 使用的问题：部分安装方式无法被 Claude++ 识别，以及卸载 Claude++ 后 Claude Desktop 仍保留第三方路由、导致消息没有输出。

## 一、修复无法找到 Claude Desktop

### 问题原因

旧版主要依赖少量固定安装路径。Claude Desktop 在 Windows 上可能通过 MSIX、Squirrel、Microsoft Store、开始菜单快捷方式或自定义目录安装；不同版本的 AppX 包名也不完全相同。macOS 同样可能安装在系统、当前用户或 Setapp 的 Applications 目录中，因此仅检查固定路径会产生误报。

### 修复内容

- Windows 新增 Squirrel、MSIX、Microsoft Store、WindowsApps 别名、注册表卸载项、开始菜单和桌面快捷方式探测。
- WindowsApps 探测不再依赖单一包名，可识别带发布者前缀的 Claude 包目录。
- macOS 新增系统 Applications、用户 Applications、Setapp 目录和 Spotlight 探测。
- 系统就绪页新增「手动选择 Claude 地址」，选择结果会持久保存，后续启动不再重复选择。
- 所有后台 PowerShell 探测均以隐藏窗口方式运行，避免点击按钮时出现终端黑框。

## 二、修复卸载后 Claude 不输出

### 问题原因

Claude++ 使用第三方 API 或 Gateway 时，会在 Claude 的 3P 配置中写入 Provider、`deploymentMode` 和当前 Provider 选择。旧版卸载程序只删除 Claude++ 本身，没有恢复这些配置。

如果卸载前使用的是本地 Gateway，Claude Desktop 仍可能继续请求 `127.0.0.1:49331`。卸载后 Gateway 已不存在，于是请求没有可用上游，表现为消息发送后没有内容输出。旧版「干净启动」还存在恢复顺序问题：先启动 Claude，再清理路由，已经启动的进程仍可能读取到旧配置。

### 修复内容

- 第一次写入 3P 配置前，记录原始 `deploymentMode`、原 Provider 选择和文件状态。
- 新增「恢复 Claude 官方配置」，无需卸载即可停止 Gateway 并清理 Claude++ 路由。
- Windows 卸载程序会在删除文件前自动执行官方配置恢复。
- 「干净启动」调整为先恢复配置、再启动 Claude Desktop。
- 兼容带 UTF-8 BOM 的 Claude JSON 配置文件，避免合法文件被误判为无法解析。
- 旧版本没有恢复快照时，也会安全移除明确属于 Claude++ 的遗留项。

## 三、兼容新版 Claude Desktop 的 CDP 启动限制

Claude Desktop `1.24012.9` 在当前 Windows 环境中会拒绝 `--remote-debugging-port` 参数并立即以退出码 `1` 结束。旧版 Claude++ 将 CDP 实时脚本视为启动的必需步骤，因此直接报告“Claude Desktop did not start”，即使 3P Provider 配置本身没有问题。

新版会先尝试实时脚本启动；确认 Claude 因 CDP 参数提前退出后，会清理失败进程并自动使用普通配置模式重新启动。此时：

- Claude Desktop 可以正常拉起。
- 直连或 Gateway 的 3P Provider 配置继续生效。
- 仅本次运行的 CDP 实时脚本不可用，界面会明确显示“CDP 已降级”，不再把整个启动判定为失败。
- 如果普通配置启动也失败，Claude++ 才会返回包含两个阶段原因的真实错误。

## 四、生产版不再依赖 localhost 开发服务

旧配置将开发预览地址 `127.0.0.1:5177` 和生产配置放在同一个 Tauri 配置文件中。Tauri 正常构建时会忽略开发地址，但旧开发入口、错误构建或遗留预览页仍可能显示 `ERR_CONNECTION_REFUSED`，容易让用户误以为 Claude++ 必须启动本地 Web 服务。

现在生产配置只包含内嵌 `frontendDist`，开发地址移动到独立的 `tauri.dev.conf.json`。只有执行 `npm run dev` 时才会加载本地预览服务；生产构建还会运行守卫检查，发现 localhost 或缺少内嵌前端目录时直接失败。

## 五、内置broken技能包支持安全卸载和重新安装

旧版只提供安装和覆盖更新，无法从软件内卸载；状态判断也只检查同名目录，无法区分 Claude++ 安装的技能和用户已有技能。

新版增加完整生命周期管理：

- 安装时写入 Claude++ 所有权清单。
- 遇到同名用户技能时，先备份原目录并记录精确恢复位置。
- 更新时沿用原始备份索引，不把上一版 Claude++ 技能误认为用户原技能。
- 卸载时先备份当前技能包，再恢复安装前存在的同名技能。
- 卸载失败或清单写入失败时自动回滚，不留下半安装状态。
- 可以在软件内反复执行安装、更新、卸载和重新安装。

## 数据保护范围

恢复操作只处理 Claude++ 自己创建或明确拥有的配置：

- 移除 `Claude++ Provider` 和旧版 `Claude++ Gateway` 条目。
- 删除这些条目引用的 Claude++ Provider 文件。
- 恢复先前的 Provider 选择；没有快照时，仅清除指向 Claude++ 的当前选择。
- 停止并关闭 Claude++ Gateway。

恢复操作不会删除：

- Claude Desktop 历史对话、账号资料和本地 Profile。
- cc-switch 配置。
- Claude++ 中保存的第三方 API Provider 列表。
- 其他工具或用户手动创建的 Provider。
- 与 Claude++ 无关的 JSON 字段和配置项。

如果配置文件已经损坏或包含无法解析的内容，Claude++ 会明确报错并停止写入，不会用空配置覆盖原文件。

## 已受影响用户如何恢复

1. 安装或运行 Claude++ `v0.1.44` 及以上版本。
2. 打开「API 配置」，点击「恢复 Claude 官方配置」。
3. 完全退出并重新启动 Claude Desktop。

也可以使用「干净启动」；新版会先完成同样的恢复，再启动 Claude Desktop。

macOS 将应用拖入废纸篓时，系统不会执行 Windows NSIS 卸载钩子。建议先在 Claude++ 中点击「恢复 Claude 官方配置」，再删除应用。

## 验证结果

- Claude++ Core：11 项测试通过，覆盖 Squirrel 和带前缀的 AppX 安装探测。
- Claude++ Desktop：5 项测试通过，覆盖 CDP 降级通道、技能包旧清单兼容、备份路径约束、有快照恢复和旧版无快照恢复。
- 使用带 UTF-8 BOM 的模拟遗留配置完成端到端恢复验证。
- 实际桌面应用已验证 Claude 地址识别、手动选择入口和恢复入口。
- 在隔离 HOME 中完成技能包“安装、卸载、恢复原技能、再次安装”的端到端验证。
- 生产 EXE 已确认不包含 `127.0.0.1:5177`，在没有本地开发服务时界面仍可正常加载。
- Windows NSIS 安装包构建成功，卸载恢复钩子已进入安装包。
